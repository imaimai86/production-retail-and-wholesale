# add-stage-model-switch

Type: feature
Priority: P2 (normal)
Source: user request in the triage conversation: "there should be a way for the user to switch model and effort dynamically in the UI before starting each stage; model selection is non-blocking (do not wait for user input); after a stage starts the model cannot be switched without stop and restart", written after PR #69 (per-stage prompt files, model and effort, shown in the pane).

## Problem
Builds on PR #69 (per-stage prompt files, model and effort; merged into `main`): `stage_model_effort`, `stage_flags`, `status.json` `models` and `stageModel` come from it. Also builds on `add-model-registry` for the list of custom models; run that item first.

Each stage's model and effort come from `stage_defaults()` and the environment (`MODEL_<STAGE>`, `EFFORT_<STAGE>`, `SDLC_MODEL`, `SDLC_EFFORT`), resolved by `stage_model_effort` (`scripts/sdlc.sh:84`) and applied by `agent()` (`scripts/sdlc.sh:112`) when the stage's agent starts. The environment is fixed when the pipeline process starts, so a developer who sees in `/sdlc-monitor` that Implement will use `sonnet · medium` cannot change it without stopping the run and starting it again with new variables. The pane shows the values (`stageModel`, `register.tsx:382`) but has no control for them. Verified by reading `scripts/sdlc.sh`, `scripts/sdlc-mod.sh` and `register.tsx`; nothing was run.

## Expected behaviour
In the pane, every stage that has not started yet shows its model and effort as two small controls. Pressing one changes the choice at once. The pipeline never waits for it: if the developer does nothing, the stage starts with the current value. When a stage's agent has started, its model and effort are shown read-only as "in use". To change them the developer stops the run and resumes at that stage, which reads the choice again.

## Decisions
- Storage: `Docs/backlog/<slug>/stage-models.txt` in the pipeline's worktree, one line per stage, `<stage-key> <model> <effort>`, for example `implement opus high`. Stage keys: `spec`, `plan`, `red-tests`, `implement`, `test-repair`, `test-audit`, `review`. One line per key; a later line for the same key wins. Blank lines and lines starting with `#` are ignored.
- Precedence in `stage_model_effort`, highest first: the line in `stage-models.txt`; `MODEL_<STAGE>` / `EFFORT_<STAGE>`; `SDLC_MODEL` / `SDLC_EFFORT`; `stage_defaults()`. A UI choice therefore overrides an environment variable for that stage, because it is the most recent and most specific choice.
- Non-blocking: `scripts/sdlc.sh` reads the file each time a stage's agent is about to start (inside `stage_flags`, and for the auditor) and never waits for it. No new gate, no new exit code, no pause. A choice made at any time before the stage starts, including while an earlier stage is running, applies.
- A malformed line (unknown key, missing field, effort outside `low|medium|high|xhigh|max`, model that does not match `^[A-Za-z0-9._:/-]+$`) is ignored with a `WARNING:` line in the run output; the stage then falls back to the next level of the precedence. It never fails the run.
- `status.json` `models` is rebuilt (same shape as today) at the start of every stage and before every agent, so it always shows what the next or current agent uses. A function `build_models_json` replaces the loop that builds `MODELS_JSON` at startup; the startup validation of the environment values stays.
- New wrapper command: `scripts/sdlc-mod.sh set-model <slug> <stage-key> <model> <effort>` writes (or replaces) that stage's line; `scripts/sdlc-mod.sh set-model <slug> <stage-key> --clear` removes it. It writes in the run's worktree. It prints one line, `<stage-key>: <model> <effort>` or `<stage-key>: default`, and exits 0.
- Locking, decided by the command from the worktree's `status.json` (`stage` and `state`) so the pane never has to guess: a stage is locked when it is before the current stage, or it is the current stage and the run `state` is `running` or `starting`, or the run `state` is `done`. Everything else is open: stages after the current one, and the current stage of a `paused`, `failed`, `interrupted` or `stopped` run (its agent is not running; resuming at it reads the choice again). Test repair covers keys `test-repair` and `test-audit`; Ship has no agent and no control. With no `status.json` yet, nothing is locked.
- Exit codes of `set-model`: 1 for a missing run record, an unknown `<stage-key>`, a model that fails the pattern above, an effort outside the list, or wrong arguments (message on stderr, nothing written); 7 (new) when the stage is locked, with the message `<stage-key> already started: stop the run and resume at <stage-key> to change its model`. Usage text lists `set-model`.
- Pane: under each stage box that has an agent, two `Button`s, `<model>` and `<effort>`. Pressing the model button cycles `opus`, `sonnet`, `haiku`, `fable`, then every `<provider>/<model>` in the model registry (`scripts/sdlc-mod.sh model list --json`, from `add-model-registry`, plus any `SDLC_PROVIDERS` entries in `.env`), then back to default (clears the line); pressing the effort button cycles `low`, `medium`, `high`, `xhigh`, `max`, then default. Each press runs `set-model` immediately, with no confirm and no wait. The pane shows the choice it read from `stage-models.txt` (a line marked with `*`, "your choice"), otherwise the `status.json` value. A locked stage shows the text `<model> · <effort> (in use)` with no buttons, and a one-line hint on a running run: `Stop and resume at <Stage> to change the model.` A rejected press (exit 7) shows a toast with the command's message and leaves the row as it was.
- The picker works with the current pane and with the layout of `add-monitor-fullscreen`, which reserves the model line of each stage box for it. Neither item depends on the other.
- Restart behaviour: `sdlc-mod.sh restart` deletes the worktree, so `stage-models.txt` is gone and defaults return. `stop` then `run` (resume) keeps it.
- `stage-models.txt` is a run file like `manual-inputs.md`: it stays in `Docs/backlog/<slug>/`; no change to what Ship commits.

## Scope
- In: `scripts/sdlc.sh` (`stage_model_effort`, `stage_flags`, `build_models_json`, header comment), `scripts/sdlc-mod.sh` (`set-model`, usage), `.claude/plugins/sdlc-monitor/hooks/register.tsx` (stage controls, lock display, toast), `.claude/plugins/sdlc-monitor/types/index.d.ts` (the selection per stage in `Run`), `README.md`, `CLAUDE.md`.
- Out of scope: a gate that waits for the choice (that is `add-stage-input-gate`, which may later show the same controls); choosing models before the run has a worktree (a queued or never-started item); changing the model of a running agent; free-text model names in the pane (the file and command accept any value that matches the pattern and, for `<provider>/<model>`, that `sdlc.sh` can resolve); editing prompt files; any change to the default table.

## Tests
- `server/__tests__/scripts/sdlc-stage-models.test.js` (extracts `stage_defaults`, `stage_model_effort`, `stage_flags` from `scripts/sdlc.sh`, as `sdlc-manual-input.test.js` does): a line in `stage-models.txt` beats `MODEL_<STAGE>`, which beats `SDLC_MODEL`, which beats the default; model and effort are taken from the same line; a later line for a key wins; comments and blank lines are ignored; each kind of malformed line gives a `WARNING:` and falls back; the file is read on every call (change it between two calls); a missing file changes nothing; `build_models_json` reflects the file.
- `server/__tests__/scripts/sdlc-mod.test.js` (throwaway git repos with a fake worktree and `status.json`): `set-model` writes, replaces and `--clear`s a line; it exits 0 for a stage after the current one and for the current stage of a paused, failed, interrupted and stopped run; it exits 7 and writes nothing for an earlier stage, for the current stage of a running or starting run, and for any stage of a done run; exit 1 for an unknown key, a bad model, a bad effort, wrong arguments and an unknown slug; two writes to different keys keep both lines.
- `.claude/plugins/sdlc-monitor/hooks/register.test.ts`: an open stage shows two buttons and a press calls `set-model` with the next value; cycling ends in a clear; a locked stage shows "(in use)", no buttons and the hint on a running run; a `*` marks a choice read from `stage-models.txt`; an exit 7 gives a toast and leaves the row unchanged; a stopped run's current stage offers the buttons.
- Integration tests: none, there is no database or API change.
