
## Round 1 (2026-10-07)

### Q1: Do `plan`, `red-tests` and `review` stay valid FROM values?
The brief says the accepted values of `FROM` are `spec`, `implement` and `test-repair`, and that any other value exits 1 with `ERROR: unknown FROM=<value> (use spec, implement or test-repair)`. It also says `FROM` "is checked only against `spec`" and that anything else silently falls through. That does not match the current `scripts/sdlc.sh`. Lines 22-25 already validate `FROM` against `spec|plan|red-tests|implement|review` and print `ERROR: unknown FROM=$FROM (use spec, plan, red-tests, implement or review)`. Lines 110-113 refuse `plan` and `red-tests` once the red-tests commit exists. Line 175 gives `review` its own resume pattern (`repair invalid tests`). Taken literally, the brief would remove three working resume points and break existing users and tests of them. The spec needs to know whether to keep them.
**Suggested:** Keep all existing values and add one: the accepted values become `spec`, `plan`, `red-tests`, `implement`, `review` and `test-repair`. The unknown-value message becomes `ERROR: unknown FROM=<value> (use spec, plan, red-tests, implement, review or test-repair)`. The check stays at the top of `scripts/sdlc.sh`, before the branch checkout. `test-repair` takes a new stage number between `implement` and `review`. The brief's other `FROM=test-repair` rules apply unchanged.
**Answer:** accept

### Q2: Which commit counts as the red-tests commit for `FROM=test-repair`, given the current resume lookup?
The brief says `FROM=test-repair` "reuses the existing resume path for the red-tests commit (`git log --grep="^test(<slug>): add failing tests"`)". The current code for resuming at Implement or Review (lines 172-178) matches either the red-tests commit or, for `review`, the later `test(<slug>): repair invalid tests` commit. The unchanged Test repair block (lines 204-229) assumes the unrepaired red-tests commit as `ORIG_RED_SHA` (`diffcheck`, `namecheck`, `redcheck`, the restore in `reject`). So `RED_SHA` must be the `add failing tests` commit only, and `resumecheck` precondition 3 (tests unchanged since that commit) is then false after an accepted repair commit. If a repair commit already exists, resuming at Test repair is probably wrong, because that stage has already been accepted.
**Suggested:** `RED_SHA` is the latest commit matching only `^test(<slug>): add failing tests`, as the brief says. If a `^test(<slug>): repair invalid tests` commit exists after it, `FROM=test-repair` fails immediately with `ERROR: test repair was already accepted in commit <sha>: use FROM=review`. This check runs before any agent call and before any file change, and it counts as one more `REJECT:` line when it is raised through the same precondition report.
**Answer:** accept
