### 2. Route validation (Implement stage), `server/index.js`
In the `app.post('/users', Auth.requireAdmin, ...)` handler, inside the `try`, before calling the model:
```js
const body = req.body && typeof req.body === 'object' && !Array.isArray(req.body) ? req.body : {};
const { name } = body;
if (name === undefined || name === null || name === '') return res.status(400).json({ error: 'name is required' });
if (typeof name !== 'string') return res.status(400).json({ error: 'name must be a string' });
if (!isNonEmptyString(name)) return res.status(400).json({ error: 'name is required' });
const user = await Users.create({ name: name.trim() });
res.status(201).json(user);
```
- Only `{ name }` is passed to `Users.create`, so extra fields are dropped and not echoed.
- Order is preserved: `Auth.verify` -> `Auth.requireAdmin` -> validation -> model. Errors from the model still go to `next(err)`.
- Whitespace-only strings fall through to the `isNonEmptyString` check and give `name is required`.
- Keep inline (matches the other routes' `isNonEmptyString(...)` checks); no new helper module needed.
- Only if the step 1 check shows it is needed: `express.json({ strict: false })` at L25.
